## Best practices

### Carbon MCP prompt writing — DOs

#### Do use the carbon-builder skill

Install the
[carbon-builder skill](/developing/carbon-mcp/onboarding-and-setup/#step-4:-adding-the-carbon-builder-skill)
and tell the AI to use it. It carries Carbon's conventions for tools, tokens,
components, accessibility, and imports.

#### Do clearly describe what you want:

- UI goal + purpose
- Framework: Carbon React v11 / Carbon Web Components v11
- Libraries needed (Core, IBM Products, icons, pictograms)
- Full component list (Grid, Header, Button, Tile, Form, etc.)
- Layout (columns, spacing, alignment, breakpoints)
- Sample data
- Exact file list to output

#### Do ask for questions and a plan first

Have the AI ask clarifying questions and propose a plan before it writes code.

### Carbon MCP prompt writing — DON'Ts

#### Don't be vague

"Build a dashboard" says nothing. Name the components, layout, data, and files.

#### Don't skip the carbon-builder skill

Without it, the AI guesses at Carbon from memory, which is often out of date.

#### Don't accept invented components or props

If the AI isn't sure something exists, it should confirm it through Carbon MCP,
not guess.

#### Don't ask for files you don't need

List the files you want, or the AI adds tests, READMEs, and config you didn't
ask for.

## Sample prompts

Sample prompts to get you started. Adapt any of them to your task.

<Accordion>
<AccordionItem title="Build a UI">

```text
Mandatory: Use the carbon-builder skill and Carbon MCP to help complete the following task:

Build a small, runnable Carbon React v11 page with a UI Shell header, a three-tile
grid, and a contact form.

Ask me any clarifying questions before you begin.

Be token-efficient: don't restate tool results, and output only package.json,
index.html, src/main.jsx, src/App.jsx, and src/styles.scss.
```

</AccordionItem>

<AccordionItem title="Apply usage and accessibility guidance">

```text
Mandatory: Use the carbon-builder skill and Carbon MCP to help complete the following task:

Check my [component or screen] against Carbon's usage and accessibility guidance.

Ask me any clarifying questions before you begin.

Be token-efficient: don't restate tool results. Give me a short, prioritized list
of changes rather than a full rewrite.
```

</AccordionItem>

<AccordionItem title="Build a chart">

```text
Mandatory: Use the carbon-builder skill and Carbon MCP to help complete the following task:

Build a runnable Carbon Charts [bar] chart in [React] using my sample data.

Ask me any clarifying questions before you begin.

Be token-efficient: don't restate tool results, and output only the files needed
to run it.
```

</AccordionItem>

<AccordionItem title="Use a Carbon Labs component">

```text
Mandatory: Use the carbon-builder skill and Carbon MCP to help complete the following task:

Add the Carbon Labs [Resizer] component to my Carbon React app.

Ask me any clarifying questions before you begin.

Be token-efficient: don't restate tool results, and output only the files you
change. Note that Carbon Labs components are experimental.
```

</AccordionItem>

<AccordionItem title="Audit existing code">

```text
Mandatory: Use the carbon-builder skill and Carbon MCP to help complete the following task:

Audit the project code against Carbon guidelines for tokens, components,
accessibility, and layout.

Ask me any clarifying questions before you begin.

Be token-efficient: don't restate tool results. Return issues grouped by severity
with the fix for each, not a full rewrite.
```

</AccordionItem>
